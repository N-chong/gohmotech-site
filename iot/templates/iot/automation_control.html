How command confirmation works
  • Sent — the command was recorded and the controller is online (it posted sensor data in the last 90 seconds). The ESP32 picks up commands on its next poll (~5 seconds).
  • Queued — the controller is offline, so the command is stored and applied once the device reconnects.
  • Online / offline is derived from recent sensor activity; the ESP32 has no dedicated heartbeat.
  • Physical confirmation is not reported by the current firmware. The device does not send back that it actually opened the door or switched the relay, so the state shown here is the requested state, not a hardware-verified one. Adding a firmware acknowledgement is the recommended next step for true end-to-end confirmation.
